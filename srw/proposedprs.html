1. Fix grblHAL hang when soft-reset arrives during $F= SD streaming Open #13

Repo: grblHAL/Plugin_SD_card   ·   Branch: stevenrwood:fix/reset-during-sd-streaming   ·   Files: fs_stream.c
The cleanup branch in onReset() required hal.stream.type == StreamType_File, which transiently becomes false during tool-change suspend_read and on_stream_changed callbacks. A reset arriving in that window leaks the file handle and the stream redirection. Symptom: grblHAL hangs and ioSender access-violates on the next command; only a Teensy power-cycle recovers it.
Verified locally: reproducible pre-fix (reset during install-probe M0 hold), clean recovery post-fix. Tightened guard fires when EITHER file.handle is open OR active_stream.type is non-Null; stream_end_job is already idempotent.

3. Honor LITTLEFS_ENABLE=2 as YMODEM request even when SDCARD is enabled Open #966

Repo: grblHAL/core   ·   Branch: stevenrwood:feat/littlefs-ymodem-combined   ·   Files: driver_opts.h
Pre-existing code in driver_opts.h demotes LITTLEFS_ENABLE from 2 to 1 whenever SDCARD is also enabled (to handle the root-mount conflict). The demotion runs before FS_ENABLE is computed, so the "=2 implies YMODEM" semantic — which works for LittleFS-alone — was unreachable in the combined config. NEWOPT advertised FS,SD instead of YM,SD; ymodem_init() never fired.
Captures the user's =2 intent into a new LITTLEFS_YMODEM_REQUESTED flag before demotion. FS_ENABLE in the combined case grants YMODEM if either SDCARD_ENABLE==2 OR LITTLEFS_YMODEM_REQUESTED. Mount-dir logic tightened to only put LittleFS at / when SDCARD is absent at build time. Tested end-to-end on Teensy 4.1.

4. Add [BUILD:...] line to $I from generated build_stamp.h Draft #967

Repo: grblHAL/core   ·   Branch: stevenrwood:feat/build-timestamp-line   ·   Files: report.c
GRBL_BUILD in grbl.h is a hand-edited integer literal that only changes when an upstream release is tagged. Operators rebuilding firmware locally have no way to confirm via $I that the running .hex matches the one they just produced. This PR adds a [BUILD:<date> <time>] line guarded by __has_include("build_stamp.h") — drivers that ship a build_stamp.h with a BUILD_TIMESTAMP macro get the line; drivers that don't are unaffected.
Marked Discuss because Terje may prefer his own build-stamping approach. Companion driver-side plumbing (a PlatformIO pre-build script regenerating build_stamp.h each build) lives in each driver, not core — keeps this PR minimal.

5. Report mDNS hostname in $I boot info Open #22

Repo: grblHAL/Plugin_networking   ·   Branch: stevenrwood:feat/hostname-boot-info   ·   Files: wiznet/enet.c
$I currently emits [IP:...] but not the hostname being broadcast over mDNS. Diagnosing "grblhal.local won't resolve" is hard when you don't know whether mDNS is silently failing, broadcasting a different name than you expect, or running fine on a network where the client just can't see it. This PR emits [HOSTNAME:<name>.local] immediately after [IP:...] when MDNS_ENABLE is set.
Single-line addition guarded by MDNS_ENABLE and a non-empty hostname check. .local suffix appended in the output (not stored) so the operator sees the exact form clients should query.

Case-insensitive LittleFS name matching Driver-local

Repo: stevenrwood/iMXRT1062 (driver fork)   ·   Branch: pr/littlefs-case-insensitive — now folded into srw/local-build-config   ·   Files: grblHAL_Teensy4/src/littlefs/lfs.c, grblHAL_Teensy4/platformio.ini
The g-code parser upper-cases O-word labels, so O<cal> CALL looks for /littlefs/CAL.macro — but LittleFS is case-sensitive while FatFs (SD) is case-insensitive, and the VFS treats the two filesystems interchangeably. A lower-case cal.macro on LittleFS then isn't found, and (because ngc_flowctrl masks the file-open failure) it surfaces misleadingly as error:81 Unknown flow statement. A build flag LFS_CASE_INSENSITIVE adds case-folded name comparison so LittleFS matches FatFs semantics — making the upper-casing a non-issue for every file operation, not just macro calls.
Not an upstream PR: it patches the driver's vendored littlefs/lfs.c, which Terje is unlikely to accept as a core/plugin change. Kept driver-local in the stevenrwood/iMXRT1062 fork instead. (Considered and rejected: a core-side CALL fallback that lower-cases the macro filename — narrower, only covers the macro path, and doesn't make the two filesystems behave consistently.)

Flow-control whitespace tolerance (O<cal> CALL) Driver-local

Repo: stevenrwood/core   ·   Branch: srw/combined (= the two core PRs + this)   ·   Files: ngc_flowctrl.c
grblHAL keeps interior spaces in a block (gc_normalize_block strips only leading whitespace), so O<cal> CALL reaches read_command with the gap intact and the keyword read lands on the space → error:81 Unknown flow statement. Skip leading spaces/tabs before reading the flow keyword so an O-word call parses with or without the gap — hand-typed at the MDI, sent by a sender that doesn't close it up, or read from a file. (Pairs with the case-insensitive littlefs fix: together they make O<cal> CALL resolve cal.macro from any sender.)
Kept driver-local (rides in the grbl srw/combined overlay) rather than filed as an upstream PR. It's a small, defensible core change and could be upstreamed later if wanted.
